# Argus

A self-contained data board: drop an Excel or CSV export in, get a dashboard you
can filter, present full-screen, hang on a warehouse TV, and hand out as a PDF.

Built as a demo/pilot for a Greek food producer & distributor (Kasidis SA
profile: meat processing, ~300 staff, HoReCa + retail + export channels), but
the engine reads column *types*, not column *names*, so any tabular export
produces a sensible board.

Live at `/argus/` on the Dion Group site.

## Why not just Power BI

Power BI is the right answer for a company that already runs Microsoft 365 with
an IT function to manage workspaces, gateways and per-seat licences. Argus
targets the case underneath that:

| | Power BI | Argus |
|---|---|---|
| Setup | Desktop authoring app (Windows), service tenant, gateway for refresh | Open a URL |
| Licence | ~€10/user/month for Pro, per viewer | none — static files |
| Where the data goes | uploaded to the Microsoft cloud | **stays in the browser tab** |
| Greek number/date formats | needs locale config, still trips on `1.234,56` | parsed natively, both conventions |
| Always-on wallboard | Premium capacity or a workaround | a mode |

The privacy line is the real one for a family-owned producer: margin and
customer data never leaves the machine, because there is no server to send it
to. That is worth more in the room than any feature.

## What it does

- **Reads** `.xlsx` / `.xlsm`, CSV, TSV, JSON — drag-drop or file picker.
- **Types** every column: date / number / text, measure vs dimension, and the
  unit (€, kg, %). Handles Greek ERP output: `;` delimiters, `1.234,56`
  decimals, `31/12/2026` dates, a title row above the table, hidden sheets.
- **Builds a starter board automatically** — KPI row, trend, mix, top-N,
  breakdown, seasonality heatmap — sized to fit the slide.
- **Filters** by period and by any dimension, applied across every card.
- **Three modes**: Studio (edit), Present (full-screen deck, arrow keys,
  auto-advance), Wallboard (always-on rotation with a clock).
- **Prints** the whole deck, one scene per A4 landscape page.
- **Saves** a workspace as a `.argus.json` file; autosaves to `localStorage`.
- **Greek and English**, switchable at any time — auto-generated titles carry an
  i18n key, so they re-label; your own titles are left alone.

## Architecture

Static files. No build step, no framework, no runtime dependency — the same
constraints as the rest of this repo, and it keeps the page inside a
`script-src 'self'` CSP.

```
argus/
├── index.html          app shell (CSP meta, hidden inputs, dialog)
├── argus.css           design tokens + layout + print stylesheet
├── js/
│   ├── app.js          state, modes, filters, tile editor, persistence
│   ├── dash.js         profiling, auto-build, scene packing, tile render
│   ├── model.js        group-by/aggregate engine, time buckets, formatting
│   ├── charts.js       SVG renderers (KPI, bar, column, line, area,
│   │                   stacked, donut, table, heatmap)
│   ├── data.js         CSV/JSON parsing, locale-aware coercion, type inference
│   ├── xlsx.js         native .xlsx reader
│   └── i18n.js         EL / EN strings
└── demo/
    ├── generate.mjs    seeded sample-data generator
    └── kasidis-sales.json
```

Three decisions worth knowing about:

**The .xlsx reader is hand-written.** A CDN is unreachable under this CSP and
SheetJS is ~900 KB anyway, so `xlsx.js` parses the ZIP container directly and
inflates each part with the platform's `DecompressionStream('deflate-raw')`,
then reads the sheet XML with `DOMParser`. About 250 lines, no dependency.
Requires Chrome 103+, Firefox 113+, Safari 16.4+; CSV is the fallback below
that.

**Charts are hand-rolled SVG**, built with `createElementNS` and
`textContent` — so customer data is never interpolated into HTML, and there is
no XSS surface. Series colours are CSS custom properties, which is why
light/dark is one token swap rather than a second palette in JS. The palette is
the validated categorical set (adjacent-pair CVD ΔE ≥ 8 in both modes, checked
against this app's own surfaces).

**A scene is a fixed 1600×900 canvas that scales to fit.** What you arrange in
Studio is exactly what the projector shows — no reflow surprises in the meeting.
Auto-build packs tiles into a 12×4 grid and spills the remainder onto a new
page rather than off the bottom of the slide.

## Running locally

```bash
python3 -m http.server 8090
# http://localhost:8090/argus/
```

Regenerate the sample data (deterministic, so the board is stable):

```bash
node argus/demo/generate.mjs
```

## Sample data

`demo/kasidis-sales.json` is **synthetic** — 14,003 order lines over 24 months,
generated by `generate.mjs` from a seeded RNG. No customer, price or volume in
it comes from a real company. It models the seasonality that makes the demo
land: the Orthodox Easter lamb spike, the summer hotel channel, the Christmas
pork peak, ~8% annual growth.

## Where this goes next

Ordered by what a pilot would need first.

1. **Scheduled feed instead of a manual upload.** The ERP writes a nightly
   CSV/JSON to a folder or URL; Argus fetches it on an interval. Read-only, no
   ERP write access, nothing for their IT to install — the easiest thing to get
   signed off. Needs `connect-src` widened to that host on a customer-hosted
   deploy.
2. **Direct connectors** — a read replica (SQL Server / MySQL) or the ERP's REST
   API. Most Greek mid-market food companies run Softone, Entersoft, Epsilon or
   Singular; each needs its own adapter, so this follows the pilot rather than
   preceding it.
3. **Calculated fields** — margin %, €/kg, price index — defined in the UI
   rather than pre-computed in the export.
4. **Targets and alerts** — a budget line on the trend, a threshold on the
   wallboard.
5. **Multi-table joins** — orders × customer master × product master.
6. **Named boards with accounts** once more than one person is authoring, which
   is the point where this stops being static files and needs a backend.
